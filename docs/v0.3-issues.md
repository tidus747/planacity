## Scope boundary

The Timeline will group by hierarchy, Epic, and WorkGroup. Grouping by Person
requires the separate multi-person Allocation entity planned for v0.4; imported
Jira assignees are baseline metadata and are not a substitute for allocations.

First-class Milestones belong to v0.6. V0.3 will not model them as zero-duration
tasks merely to draw markers. When Milestones exist, the Timeline can visualize
them from the same canonical model.

## Direct date editing and dependency arrows

Bar-edge resizing is a focused v0.3 follow-up after the day/week/month scales.
Drag the left or right edge to adjust a scheduled item's start or end date, with
day snapping, a proposed-date preview, and one validated update on release.
Escape or an invalid drop preserves the original schedule. Dates remain inclusive
and cannot cross. Keyboard date editing must remain available.

Changing a date range does not change estimated effort hours, move dependent work,
or overwrite an imported baseline. Partial and unscheduled work continues to use
the date editor. This work is planned, not enabled in the current read-only view.

Dependency arrows are implemented for review in #34. For A depends_on B, draw B -> A; for A blocks
B, draw A -> B. Parent/child hierarchy and related_to are separate concepts.
Show accessible relationship details and handle hidden or unscheduled endpoints
without misleading arrows. Displaying a dependency does not automatically move work.
The #35 acceptance pass should also cover bar resizing when #50 is implemented.

Whole-bar moving, automatic dependency scheduling, capacity, timeline export,
and scenario comparison remain outside this focused interaction change.
