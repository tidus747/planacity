# Planacity v0.5.0-dev.0 - Program Calendar preview

Prepared release notes. This document does not publish a tag, GitHub prerelease,
or executable download.

Planacity 0.5 brings work, team capacity, shared events, and manual sprints into
one local planning workspace. This development preview is intended for early
Windows feedback before stable installer support.

## What you can do

- Create shared holidays and program events, with explicit capacity impact.
- Review events in Calendar, Overview, and optional Timeline lanes.
- Import generic availability CSV files through explicit field and person
  mappings, complete row review, and deliberate selection.
- Create first-class sprints, assign executable leaf work explicitly, and review
  exact capacity, competing demand, incomplete inputs, and graphical sprint
  lanes.
- Explore Team Timeline lanes, availability overlays, dependency graphs, and
  dependency-only critical-path analysis.
- Keep executable work assigned to zero or one person while preserving and
  explicitly resolving legacy multiple assignments.
- Link planned work to compatible capacity reservations without counting covered
  hours twice.
- Use the version-matched offline planning guide from Help or About without
  sending plan data or requiring an account.

## Windows portable preview

The planned assets are:

```text
Planacity-v0.5.0-dev.0-windows-x64.zip
Planacity-v0.5.0-dev.0-windows-x64.zip.sha256
```

The ZIP is a portable, unsigned Windows x64 application. Extract the complete
directory before running `Planacity.exe`. It does not require Python, but it is
not an installer and does not create shortcuts, register file associations, or
provide automatic updates. Windows SmartScreen may show an unknown-publisher
warning because the executable is not code-signed.

Wheel and source installations require Python 3.11 through 3.14. The portable
Windows ZIP includes its own runtime.

The bundle includes the GPL license, a Windows quick-start guide, and the
fictional Moon Heist example. Planning data stays in local files and no account
or cloud service is required.

## Compatibility and boundaries

Projects save as schema 14. Schemas 1-13 remain readable. Preserve a backup or
use Save As if an older Planacity build must still open the original file.

Jira interoperability remains explicit CSV import/export. Additive imports can
use existing external references only as unchanged hierarchy anchors; full Jira
re-import reconciliation belongs to v0.8. Jira REST, automatic sprint
distribution, Factorial-specific mapping, Milestones, Deliveries, report export,
and a stable signed installer are not included.

## Validation and publication

The reviewed release commit must be on `main` with CI and the Windows portable
workflow passing. Publication requires separate approval of that exact commit,
an annotated `v0.5.0-dev.0` tag, and a GitHub prerelease using the existing tag.
Verify the published ZIP against its SHA-256 checksum before advertising it on
the website. Follow the [release procedure](../releasing.md).
