# v0.2 - Jira Roundtrip

Goal: bring Jira work into Planacity and export the agreed structure.
Target: v0.2.0. Publishing requires a reviewed main commit and passing CI.

Tracked in GitHub issues [#21](https://github.com/tidus747/planacity/issues/21),
[#22](https://github.com/tidus747/planacity/issues/22),
[#23](https://github.com/tidus747/planacity/issues/23),
[#24](https://github.com/tidus747/planacity/issues/24), and
[#25](https://github.com/tidus747/planacity/issues/25), respectively.
Implemented on the Jira Roundtrip branch; review and release publication remain pending.

## V02-01 - Parse and validate mapped Jira CSV

- Read UTF-8 CSV, including quoted multiline cells and repeated column headers.
- Map columns by position, estimates with explicit units, and dates with an
  explicit format. Never interpret story points as hours.
- Validate duplicate references, missing parents, types, estimates, and dates.
- Report row-specific errors and leave the active plan untouched on failure.

## V02-02 - Preserve imported baselines in project files

- Keep source cells, external references, and original work snapshots locally.
- Map external people to existing or explicitly created roster entries.
- Save/open and JSON backup retain baseline data unchanged after local edits.
- Read existing v0.1 projects; reject unsupported newer schemas.

## V02-03 - Add an import wizard and reusable profiles

- Choose a CSV, map columns and people, validate, preview, then confirm import.
- Cancellation never changes the document.
- Save reusable column profiles locally, excluding person identities and data.
- Expose errors with actionable guidance in both appearances.

## V02-04 - Export Jira CSV and show changes

- Export hierarchy in parent-first order with IDs and external references.
- Make column labels, estimate units, and date format explicit.
- Show added, modified, and removed work relative to the preserved baseline.
- Document fields omitted from Jira exports; never imply deleting a CSV row
  deletes a Jira issue. Do not modify baselines when exporting.

## V02-05 - Validate and document the complete roundtrip

- Include fictional CSV data and import/edit/save/reopen/export acceptance tests.
- Update the website, user documentation, and changelog with actual capabilities.
- Run Windows/Linux CI, package and website builds, and Windows UI checks.
- Prepare v0.2.0 release notes without publishing a tag before approval.

Re-import reconciliation, Jira APIs, allocations, and capacity remain deferred.
