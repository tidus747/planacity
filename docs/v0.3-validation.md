# v0.3 Visual Planning validation

Validation date: 2026-09-29. Target: v0.3.0 source release candidate.
Publication and final main-branch CI remain separate release gates.

## Acceptance evidence

| Area | Evidence |
| --- | --- |
| Canonical projection | Hierarchy order, stable IDs, inherited groups, inclusive dates, and explicit incomplete/outside-horizon states |
| Scales | Day, ISO week, and calendar month; leap days and supported date limits; stable selection and local preference |
| Grouping and filters | Hierarchy/Epic/WorkGroup, repeated memberships, unique counts, standalone/ungrouped sections, combined filters and clearing |
| Dependencies | Canonical direction, orthogonal geometry, cycles, overlaps, hidden endpoints, scrolling, both appearances |
| Date editing | Both handles at all scales, preview, Escape/invalid-drop cancellation, stale snapshot protection, keyboard/calendar entry |
| Integrity | Estimates and imported baselines preserved; Plan/Changes synchronized; save/reopen roundtrip |
| Example workflow | Shipped Aurora example exercised end to end in light and dark appearance |

The local automated suite passes 297 tests on Windows with Python 3.12 and
PySide6 6.11.2. Ruff lint/format checks and strict mypy pass. A separate native
Windows Qt run passes 28 tests covering the example walkthrough, resizing,
grouping/dependencies, and calendar appearance. Screenshot review covers real
light/dark views; images are linked from the getting-started guide.

The new example checks are in `tests/test_visual_planning_acceptance.py`.
Existing Timeline, calendar, persistence, and Jira tests cover the detailed cases.
The example has 9 scheduled, 2 partial, and 1 unscheduled item. The original
schema 1 backup remains unchanged by the walkthrough; saving writes schema 2.

## Build checks

- Build the wheel and source distribution using `python -m build`.
- Install the wheel with its declared dependencies into a fresh virtual
  environment. Confirm version 0.3.0 imports from site-packages, loads bundled
  icons, opens the example, and launches the Timeline through a Qt event loop.
- Build the Astro website with Node 22 and `npm run build`.
- Require the integration PR's CI matrix to pass on Windows and Linux with
  Python 3.11 and 3.13, including tests and distribution builds. Website CI is
  also required. Pages deployment occurs from main after successful checks.

The local package/install/launch and website checks passed. These artifacts are
validation outputs, not published downloads or standalone installers.

## Limits and deferred work

Linux coverage is automated/offscreen; a manual Linux desktop review and a
standalone Windows installer are not claimed. Large-project performance,
broader assistive-technology testing, and installer validation remain
stabilisation work. This is not a claim of production certification.

Person grouping needs Allocations in v0.4. First-class Milestones in v0.6 are
required before drawing milestone markers. Capacity, scenarios, Timeline export,
automatic scheduling, whole-bar moving, and an undo framework remain deferred.
Resize by scrolling first or use Edit dates; dragging does not auto-scroll.
